# راهنمای ایجاد پرسنل و حساب‌های ورود

این راهنما مربوط به فاز سوم تأییدشده در ۱۰ نوامبر ۲۰۲۶ است. از [فهرست پرسنل](http://localhost:8081/admin/personnel) استفاده کنید. ورود، خروج، فراخوانی API و callbackها همچنان روی پورت ۸۰۸۱ هستند. پورت مدیریت Keycloak مسیر ورود عادی کاربران نیست.

## مجوزهای لازم

برای مشاهدهٔ فهرست، مجوز `personnel.view` لازم است. دو اختیار زیر مستقل‌اند و باید سراسری باشند:

| مجوز | کاربرد |
| --- | --- |
| `personnel.create` | نمایش «افزودن پرسنل» و ایجاد مشخصات فرد؛ بدون نیاز به مجوز ویرایش |
| `personnel.members.manage` | مشاهده، جست‌وجو، اتصال و حذف حساب‌های ورود فرد |
| `personnel.update` | ویرایش نام و محل استقرار؛ این اختیار به‌تنهایی اجازهٔ ایجاد یا مدیریت اتصال نمی‌دهد |

مجوز شرکتی برای تغییر مشخصات مشترک یا حساب‌های ورود کافی نیست. در این محیط، با درخواست صریح کاربر، هر دو مجوز جدید به نقش «مدیر سامانه» اضافه شده‌اند. برای دیدن دکمه‌ها، صفحه را بازخوانی کنید؛ ورود مجدد لازم نیست.

## ایجاد پرسنل

۱. محدودهٔ فهرست را روی «سراسری» بگذارید و «افزودن پرسنل» را بزنید.
۲. نام و نام خانوادگی و ساختمان و ناحیهٔ استقرار را انتخاب کنید؛ هر دو الزامی‌اند.
۳. «ایجاد پرسنل» را بزنید. ابتدا فقط مشخصات محلی فرد ذخیره می‌شود و هیچ حساب یا رمز Keycloak ساخته نمی‌شود.
۴. پس از ایجاد، از ردیف همان فرد وارد «حساب‌های ورود» شوید.

فرد بدون حساب ورود نیز در فهرست باقی می‌ماند. ایجاد فرد، نقش، سمت یا عضویت شرکت ایجاد نمی‌کند. نام و محل استقرار ثبت‌شده با اتصال حساب یا ایمپورت به همان فرد جایگزین نمی‌شود.

## اتصال حساب موجود

۱. «حساب‌های ورود» را در ردیف فرد بزنید و یک منبع فعال انتخاب کنید.
۲. نام کاربری، نام، نام خانوادگی یا ایمیل را جست‌وجو کنید. نتایج مستقیماً از Keycloak همان منبع دریافت می‌شوند.
۳. اطلاعات حساب را بررسی و یک حساب مجاز را انتخاب کنید؛ سپس «اتصال حساب انتخاب‌شده» را بزنید.

از هر منبع فقط یک حساب می‌توان به یک فرد وصل کرد. اگر قبلاً اتصالی از همان منبع وجود دارد، جست‌وجو غیرفعال است؛ ابتدا اتصال قبلی را حذف کنید. برای حساب از منبع دیگر می‌توانید اتصال جدا بسازید.

حسابی که به فرد دیگری وصل است نمایش داده می‌شود، نام آن فرد را هم می‌بینید، اما انتخاب آن مجاز نیست. انتقال خودکار وجود ندارد؛ مدیر مجاز باید ابتدا اتصال قبلی را حذف کند. حساب غیرفعال Keycloak نمایش داده می‌شود ولی قابل اتصال نیست؛ حساب‌های سیستمی سرویس‌ها در نتایج نمی‌آیند. اگر وضعیت حساب یا تنظیمات منبع هنگام کار تغییر کند، اتصال رد می‌شود و باید دوباره جست‌وجو کنید.

صفحهٔ بعد ممکن است حتی پس از یک صفحهٔ بدون نتیجه وجود داشته باشد، چون حساب‌های سیستمی از صفحهٔ دریافتی حذف می‌شوند. از دکمه‌های صفحه‌بندی استفاده کنید؛ همهٔ حساب‌ها در یک پاسخ بارگیری نمی‌شوند.

## نشان اتصال فعال

نشان هشدار با آیکون اتصال قطع‌شده و متن «فاقد اتصال به منبع فعال» کنار این افراد ظاهر می‌شود:

- فردی که هیچ Member ندارد؛
- فردی که همهٔ اتصال‌هایش به منابع غیرفعال است.

وجود حتی یک اتصال به منبع فعال، نشان را برمی‌دارد. پس از بستن پنجرهٔ حساب‌ها، فهرست تازه می‌شود. این نشان وضعیت اتصال و فعال‌بودن منبع را نشان می‌دهد؛ سالم‌بودن شبکه، فعال‌بودن حساب خارجی یا اعتبار هر ورود را تضمین نمی‌کند.

## حذف اتصال

در حساب‌های متصل، «حذف اتصال» را بزنید و پیام را تأیید کنید. رکورد Member و تمام توکن‌های ورود مربوط به همان اتصال در سامانه حذف می‌شوند. حساب Keycloak و نشست سازمانی آن با این عملیات تغییر نمی‌کنند. ورودهای مربوط به Memberهای دیگر همان فرد برقرار می‌مانند، مگر بررسی عادی اعتبار ورود آن‌ها را رد کند.

حذف آخرین Member هم مجاز است؛ حتی اگر فرد مدیر سامانه باشد. مشخصات، محل، تنظیمات ظاهر، سمت‌ها و نقش‌ها باقی می‌مانند، اما فرد تا اتصال دوبارهٔ یک حساب راه ورود ندارد. اگر حساب مربوط به مرورگر فعلی را حذف کنید، بلافاصله به صفحهٔ ورود برمی‌گردید. اتصال مجدد، توکن‌های قبلاً حذف‌شده را زنده نمی‌کند.

اتصال منبع غیرفعال نیز دیده می‌شود و قابل حذف است. اگر اطلاعات حساب از منبع دریافت نشود، شناسهٔ محلی اتصال همچنان نمایش داده می‌شود. خود حذف به خواندن حساب خارجی نیاز ندارد؛ با این حال، بررسی عادی اعتبار ورود اپراتور برقرار است و اختلال سرویس هویت ممکن است پیش از اجرای عملیات دسترسی او را متوقف کند.

## ارتقای دیتابیس و تعارض‌های قبلی

فرمان‌ها از ریشهٔ مخزن اجرا می‌شوند:

```bash
docker compose exec -T backend php artisan migrate --force --no-interaction
docker compose exec -T backend php artisan access:sync-permissions
```

مهاجرت جدید علاوه بر یکتایی حساب خارجی در هر منبع، یکتایی `(user_id, user_source_id)` را اعمال می‌کند. اگر از قبل برای یک فرد چند Member از یک منبع وجود داشته باشد، مهاجرت با شناسه‌های محلی متعارض متوقف می‌شود و چیزی را خودکار حذف نمی‌کند. اپراتور مجاز باید حساب موردنظر را مشخص و اتصال‌های اضافی را آگاهانه برطرف کند؛ حذف از مسیر سامانه، توکن‌های همان اتصال را هم لغو می‌کند. تا رفع تعارض، محدودیت را با تغییر دستی migration یا پاک‌کردن اطلاعات دور نزنید. پس از اصلاح تأییدشده، مهاجرت را دوباره اجرا کنید.

ستون وضعیت جداگانه‌ای برای نشان فهرست ذخیره نمی‌شود؛ وضعیت از داده‌های فعلی محاسبه می‌شود. تنظیمات منابع، `slug` عمومی و کلید عددی رابطهٔ Member تغییر نکرده‌اند.

## مجوزدهی هنگام ارتقا

همگام‌سازی، دو مجوز جدید را در کاتالوگ ثبت می‌کند ولی آن‌ها را خودکار به نقش مدیر از قبل موجود نمی‌دهد. نقش مدیر تازه‌ساخته‌شده کاتالوگ را دریافت می‌کند. `access:bootstrap` صرفاً نقش موجود مدیر را به حساب تعیین‌شده می‌دهد و مجوزهای حذف‌شدهٔ آن نقش را بازسازی نمی‌کند.

اگر مدیر مجاز این دو اختیار را دارد، می‌تواند از صفحهٔ نقش‌ها آن‌ها را جداگانه به نقش‌های دیگر بدهد. واگذارکننده باید خودش اختیار موردنظر را داشته باشد. اگر در محیط ارتقایافته هیچ واگذارکننده‌ای مجوز جدید ندارد، اپراتور دارای دسترسی سرور باید پس از تأیید نقش مقصد، اعطای اولیه را صریحاً انجام دهد. نمونهٔ زیر فقط همین دو مجوز را به نقش دارای کلید مشخص اضافه می‌کند و سایر مجوزها و تخصیص کاربران را حفظ می‌کند؛ `ROLE_KEY` را با کلید نقش تأییدشده جایگزین کنید:

```bash
docker compose exec -T backend php /dev/stdin ROLE_KEY <<'PHP'
<?php
require 'vendor/autoload.php';
$app = require 'bootstrap/app.php';
$app->make(Illuminate\Contracts\Console\Kernel::class)->bootstrap();
App\Modules\Organization\Actions\AtomicChange::run(function () use ($argv) {
    $role = App\Modules\Access\Models\Role::where('key', $argv[1])->lockForUpdate()->firstOrFail();
    $permissions = App\Modules\Access\Models\Permission::whereIn('key', [
        'personnel.create', 'personnel.members.manage',
    ])->get();
    if ($permissions->count() !== 2) {
        throw new RuntimeException('Run access:sync-permissions first.');
    }
    foreach ($permissions as $permission) {
        Illuminate\Support\Facades\DB::table('role_permission')->insertOrIgnore([
            'role_id' => $role->id, 'permission_id' => $permission->id,
        ]);
    }
});
PHP
```

برای تفکیک اختیارها، فقط کلید مجوز تأییدشده را در فهرست بگذارید و کنترل تعداد را متناسب کنید. این نمونه دستور اعطای خودکار هنگام استقرار نیست. در محیط فعلی، اعطای هر دو به «مدیر سامانه» قبلاً با تأیید صریح انجام شده است.

## ورود گروهی

قابلیت ایمپورت باقی است. برای حساب‌های جدید، محل اولیه را صریح مشخص کنید؛ برای اتصال به User موجود از فایل نگاشت خصوصی استفاده کنید:

```bash
docker compose exec -T backend php artisan login:import-members --source=primary --building-area=AREA_ID --dry-run
docker compose exec -T backend php artisan login:import-members --source=primary --building-area=AREA_ID
docker compose exec -T backend php artisan login:import-members --source=primary --mapping-file=/run/organization/member-map.json --dry-run
```

قالب نگاشت:

```json
{"external-subject": 123}
```

مسیر فایل باید داخل کانتینر قابل خواندن و خارج از Git باشد. استفاده از نام و ایمیل برای نگاشت خودکار مجاز نیست. `--source` همیشه slug است. اجرای دوبارهٔ همان اتصال تکرار ایجاد نمی‌کند. حساب غیرفعال یا سیستمی ایمپورت نمی‌شود.

اگر چند حساب یک منبع به یک User نگاشت شوند، یا حسابی به فرد دیگری متصل باشد، ایمپورت با خطای مشخص متوقف می‌شود. `dry-run` همین تعارض‌ها را حتی میان ورودی‌های همان فایل تشخیص می‌دهد و در دیتابیس برنامه نمی‌نویسد. اجرای واقعی، ورودی‌های تکمیل‌شدهٔ قبل از خطا را نگه می‌دارد؛ کل دسته یک تراکنش واحد نیست. پس از رفع تعارض دوباره اجرا کنید. ایمپورت را برای بازگرداندن اتصال حذف‌شده فقط با تصمیم صریح اپراتور اجرا کنید.

## رفع مشکل

| نشانه | اقدام |
| --- | --- |
| دکمهٔ ایجاد یا حساب‌های ورود دیده نمی‌شود | مجوز مستقل سراسری و مجوز مشاهدهٔ فهرست را بررسی و صفحه را بازخوانی کنید. |
| منبع در انتخاب نیست | فقط منابع فعال قابل انتخاب‌اند؛ اتصال‌های قدیمی آن را در بخش حساب‌های متصل ببینید. |
| جست‌وجوی منبع غیرفعال است | اتصال همان منبع برای فرد وجود دارد؛ ابتدا در صورت نیاز همان اتصال را حذف کنید. |
| حساب متعلق به فرد دیگری است | نام مالک نمایش داده می‌شود؛ اتصال خودکار یا انتخاب حساب اشغال‌شده مجاز نیست. |
| دسترسی جست‌وجو تنظیم نشده یا در دسترس نیست | تنظیمات خصوصی `import_client_id`، `import_client_secret`، `admin_base_url`، دسترسی خواندن کاربران و سلامت منبع را بررسی کنید. رمزها را در خروجی اشتراکی قرار ندهید. |
| پس از حذف آخرین اتصال فرد نمی‌تواند وارد شود | یک حساب از منبع فعال را با مجوز مدیریت اتصال به همان User متصل کنید؛ User یا رمز محلی جدید نسازید. |

قرارداد دقیق API و کدهای خطا در [مستندات فنی این فاز](../technical/personnel-account-connections.md) آمده‌اند.
