# مدیریت سورس‌های ورود

این راهنما مربوط به فاز چهارم تأییدشده است. صفحهٔ [سورس‌های ورود](http://localhost:8081/admin/login-sources) از منوی «مدیریت سازمان ← دسترسی‌ها ← سورس‌های ورود» باز می‌شود. هر سورس یک اتصال مستقل به Keycloak است؛ افزودن سورس در این صفحه، در Keycloak کاربر، realm یا کلاینت نمی‌سازد.

## دسترسی و آماده‌سازی مجوزها

مشاهده، ایجاد، ویرایش، تغییر وضعیت و حذف، مجوزهای سراسری جداگانه دارند:

| عملیات | مجوز |
| --- | --- |
| مشاهده | `login_sources.view` |
| افزودن | `login_sources.create` |
| ویرایش | `login_sources.update` |
| فعال یا غیرفعال‌کردن | `login_sources.activate` |
| حذف | `login_sources.delete` |

مجوز محدود به یک شرکت برای این بخش کافی نیست. منو با مجوز مشاهده و هر دکمه با مجوز همان عملیات نمایش داده می‌شود.

برای ثبت یا به‌روزرسانی فهرست مجوزها، از ریشهٔ مخزن اجرا کنید:

```bash
docker compose exec -T backend php artisan access:sync-permissions
```

این فرمان در محیط توسعهٔ فعلی اجرا شده و دسترسی مدیر موجود بررسی شده است. پنج مجوز جدید به نقش `system-administrator` اضافه می‌شوند؛ فرمان، این نقش را به کاربر جدید تخصیص نمی‌دهد و نقش‌های سفارشی را گسترش نمی‌دهد. برای نقش سفارشی، مدیر مجاز باید مجوزهای لازم را از پنل نقش‌ها تعیین کند.

## افزودن سورس

۱. «افزودن سورس» را بزنید و عنوان نمایشی و شناسهٔ یکتای لاتین، مانند `head-office`، را وارد کنید. شناسه پس از ایجاد تغییر نمی‌کند.

۲. آدرس کامل صادرکنندهٔ عمومی، آدرس داخلی همان realm، شناسه و رمز کلاینت موجود در Keycloak را وارد کنید. آدرس داخلی برای ارتباط سرور است و نباید به یک صادرکنندهٔ دیگر اشاره کند.

۳. آدرس‌های بازگشت نمایش‌داده‌شده را در کلاینت Keycloak تنظیم کنید. بازگشت ورود روی `/login/callback/{slug}` و بازگشت خروج روی `/login/logged-out` در مبدأ اصلی سامانه است. پورت مدیریتی ۸۰۸۳ را برای مسیر ورود برنامه استفاده نکنید.

۴. اگر جست‌وجو یا واردکردن حساب‌های پرسنل لازم است، گزینهٔ مربوط را روشن و شناسه، رمز کلاینت خواندن کاربران و آدرس API مدیریت همان realm را تکمیل کنید. هر سه مقدار لازم‌اند. این کلاینت باید دسترسی خواندن کاربران داشته باشد.

۵. مهلت پاسخ را بین ۱ تا ۳۰ ثانیه و تعداد کاربران هر صفحهٔ واردسازی را بین ۱ تا ۵۰۰ تعیین کنید. پیش‌فرض‌ها ۱۰ ثانیه و ۱۰۰ کاربرند؛ الگوریتم امضا RS256 است.

۶. سورس را ذخیره کنید. سورس جدید غیرفعال ساخته می‌شود؛ پس از بررسی تنظیمات، از فهرست آن را فعال کنید. فعال‌سازی صرفاً مجوز استفاده از تنظیمات است و به معنی موفقیت آزمون اتصال نیست.

برای ورود، حساب Keycloak باید از قبل به پرسنل محلی متصل یا وارد شده باشد. ورود ناشناس به‌صورت خودکار پرسنل نمی‌سازد و تشابه نام یا ایمیل باعث اتصال خودکار نمی‌شود. [راهنمای اتصال حساب‌ها](personnel.fa.md) مراحل مربوط را توضیح می‌دهد.

## ویرایش و نگهداری رمزها

فیلد رمز ذخیره‌شده همیشه خالی است؛ پیام زیر آن مشخص می‌کند رمز قبلاً تنظیم شده یا نه. برای حفظ رمز، فیلد را خالی بگذارید. برای تعویض، مقدار کلاینت موجود در Keycloak را وارد کنید. این فرم، رمز کلاینت را در خود Keycloak تغییر نمی‌دهد.

تغییر عنوان یا تنظیمات خواندن کاربران، ورودهای معتبر سورس فعال را قطع نمی‌کند. تغییر تنظیمات امنیتی مانند آدرس‌های ورود، شناسه یا رمز کلاینت، توکن‌های محلی همان سورس را باطل می‌کند و تأیید جداگانه دارد؛ کاربران باید دوباره وارد شوند. اگر با همان سورس وارد شده باشید، دسترسی فعلی شما هم قطع می‌شود.

خاموش‌کردن «جست‌وجو و اتصال حساب‌های پرسنل» و ذخیره، تنظیمات و رمز کلاینت خواندن کاربران را به‌صورت یکجا حذف می‌کند؛ اتصال‌های قبلی حذف نمی‌شوند.

صادرکنندهٔ عمومی سورس دارای حساب متصل قابل تغییر نیست. برای اتصال به یک مرجع هویت دیگر، سورس جدید بسازید و حساب‌ها را صریحاً متصل کنید.

## فعال‌سازی، غیرفعال‌سازی و حذف

غیرفعال‌کردن، سورس را از انتخاب ورود پنهان می‌کند و تمام توکن‌های محلی صادرشده از آن را باطل می‌کند. ورود جدید و جست‌وجو/اتصال حساب جدید از آن متوقف می‌شود. پرسنل، اتصال‌های محلی و حساب‌های Keycloak حفظ می‌شوند؛ اتصال‌های قبلی از بخش حساب‌های ورود پرسنل همچنان قابل مدیریت‌اند.

با فعال‌سازی دوباره، کاربران باید ورود تازه انجام دهند؛ توکن‌های باطل‌شده برنمی‌گردند. این عملیات نشست یا حساب کاربر را در Keycloak حذف نمی‌کند.

حذف فقط برای سورس بدون هیچ حساب متصل مجاز است. سورس دارای اتصال را می‌توان غیرفعال کرد. حذف سورس بدون اتصال فقط رکورد محلی تنظیمات را حذف می‌کند.

سامانه مانع غیرفعال‌کردن آخرین سورس فعال نمی‌شود. پیش از تأیید، مطمئن شوید مسیر بازیابی عملیاتی را دارید؛ اگر همهٔ سورس‌های قابل استفاده خاموش شوند، ورود مدیر از پنل هم ممکن نخواهد بود.

## مبداهای مجاز سرویس هویت

مسئول استقرار، مبداهای مجاز را در `LOGIN_SOURCE_ALLOWED_ORIGINS` با ویرگول جدا می‌کند. مبدأ شامل پروتکل، میزبان و پورت است؛ مسیر realm در خود سورس تعیین می‌شود. پیش‌فرض توسعه:

```dotenv
LOGIN_SOURCE_ALLOWED_ORIGINS=http://localhost:8081,http://keycloak:8080,http://keycloak-secondary:8080
```

برای افزودن مبدأ دیگر، مقدار `.env` را تنظیم و فقط سرویس بک‌اند را با محیط جدید بازسازی کنید:

```bash
docker compose up -d --no-deps backend
```

این کار کانتینر بک‌اند را دوباره ایجاد می‌کند و داده‌های پایدار را حفظ می‌کند. متغیر محیطی جدید باید در همان استقرار اعمال شود؛ تغییر فایل به‌تنهایی محیط کانتینر موجود را عوض نمی‌کند. خارج از Compose، مقدار پیش‌فرض فهرست خالی است و مسئول استقرار باید آن را صریحاً تعیین کند.

خواندن سورس‌های موجود با آدرس تغییریافته‌نشده ادامه دارد؛ افزودن یا تغییر آدرس باید از فهرست مجاز پیروی کند. آدرس دارای نام کاربری، رمز، query یا fragment پذیرفته نیست؛ در محیط production آدرس سرویس باید HTTPS باشد.

## بازیابی بدون پنل

اگر آخرین سورس را غیرفعال کرده‌اید یا تنظیمات کلاینت اشتباه است، مسئول محیط می‌تواند با فرمان موجود آن را اصلاح کند. از فایل خصوصی کامل مربوط به همان سورس استفاده کنید؛ در آن `is_active` را `true` و تنظیمات کلاینت را با Keycloak هماهنگ کنید. قالب کامل فایل در [مستندات دیتابیس](../technical/database.md) آمده است.

```bash
docker compose exec -T backend php artisan login:sources:upsert --config-file=/run/organization/sources/primary.json
```

این مسیر به فایل خصوصی `.runtime/sources/primary.json` روی میزبان مربوط است. فایل نمونه یا فایل سورس دیگری را بی‌بررسی جایگزین تنظیمات واقعی نکنید. فرمان خطا را بدون چاپ رمز گزارش می‌کند؛ کد خروج غیرصفر یعنی تغییر موفق نبوده است.

برخلاف ویرایش جزئی در API، فرمان CLI فایل کامل با رمزهای واقعی همان کلاینت و آدرس‌های بازگشت صحیح می‌خواهد؛ رمز خالی را به معنی «حفظ مقدار قبلی» در فایل CLI استفاده نکنید. همان محدودیت شناسهٔ ثابت، صادرکنندهٔ دارای اتصال، مبداهای مجاز و ابطال توکن در CLI هم اعمال می‌شود.

پس از اصلاح، دوباره وارد شوید. این فرمان کاربر جدید، حساب متصل یا مجوز مدیر ایجاد نمی‌کند؛ دسترسی سراسری مدیر باید از قبل وجود داشته باشد. برای مشکل تخصیص نقش، [راهنمای مدیریت دسترسی](organization.fa.md) را ببینید. اسکریپت bootstrap فایل‌های سورس توسعه را از `.env` بازتولید می‌کند؛ برای منابع سفارشی فایل خصوصی جدا نگه دارید و هر بازاجرای راه‌اندازی را با تغییرات پنل هماهنگ کنید.

## عیب‌یابی کوتاه

| نشانه | اقدام |
| --- | --- |
| منو یا دکمه دیده نمی‌شود | همگام‌سازی مجوزها و تخصیص سراسری نقش/مجوز همان عملیات را بررسی کنید. |
| آدرس مبدأ مجاز نیست | مسئول استقرار باید فهرست مجاز و اعمال آن روی کانتینر را بررسی کند. |
| سورس فعال است ولی ورود کار نمی‌کند | سلامت Keycloak، realm، کلاینت، callback، رمز و اتصال قبلی حساب به پرسنل را بررسی کنید. |
| جست‌وجوی حساب‌ها در دسترس نیست | هر سه تنظیم خواندن کاربران، مجوز کلاینت و سلامت سرویس را بررسی کنید. |
| حذف رد می‌شود | سورس حساب متصل دارد؛ آن را غیرفعال کنید یا اتصال‌ها را صریحاً از پرسنل مدیریت کنید. |
| پس از تغییر رمز کلاینت از سامانه خارج شدید | اثر مورد انتظار ابطال توکن است؛ با تنظیمات معتبر دوباره وارد شوید. |

گوگل و Laravel Passport در این فاز به‌صورت مستقیم پشتیبانی نمی‌شوند؛ صرف واردکردن آدرس آن‌ها در فرم کافی نیست. طرح اتصال ارائه‌دهندهٔ دیگر و هماهنگی خروج، خارج از محدودهٔ این فاز است.
